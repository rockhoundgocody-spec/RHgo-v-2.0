## 2025-02-13 - Mitigating Open Redirect Vulnerabilities in Client Redirection and Callback Flows
**Vulnerability:** Open Redirect vulnerability via the unsanitized `from_url` query parameter on the frontend, and potential open redirects in callback handler URLs (`successUrl` and `cancelUrl`) within `createCheckoutSession` server function. Attackers could craft links pointing to malicious third-party locations to deceive users during logout/checkout redirects.
**Learning:** Redirection parameters like `from_url`, `successUrl`, and `cancelUrl` were trusted and parsed without strict white-listing or validation. In ESM testing environments like Node/Vitest, mocking browser globals such as `window` requires configuring `localStorage` to avoid evaluation-time `TypeError` exceptions when code dynamically references storage attributes.
**Prevention:** Implement standard origin-filtering helper functions like `getSafeRedirectUrl` and `isValidRedirectTarget` to sanitize all redirection parameters, strictly allowing same-origin absolute paths, relative paths starting with a single `/` (avoiding bypasses like `//` or `/\`), or verified domains/hostnames (e.g., `.base44.app`).
