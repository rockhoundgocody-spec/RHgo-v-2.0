## 2026-07-20 - Open Redirect and Token Leakage Mitigation in App Config
**Vulnerability:** The application parsed redirect and from_url parameters from search parameters and stored sensitive tokens ('access_token', 'token') in persistent `localStorage`. This could allow attackers to perform Open Redirect attacks by providing malicious URLs, and persistent `localStorage` increased the risk of token theft (XSS/device leakage) compared to transient `sessionStorage`.
**Learning:** Storing authentication parameters like access tokens in `localStorage` persists the session across browser closures, which is unsafe for public terminals or highly sensitive tokens. Furthermore, accepting external from_url query parameters directly as destinations without checking if they match the current origin allows malicious actors to construct phishing links targeting users.
**Prevention:** Always route access tokens and session-specific auth tokens dynamically to `sessionStorage` rather than persistent `localStorage`, proactively purge legacy keys from `localStorage` on initialization, and always validate any redirect target URL using a strict helper like `getSafeRedirectUrl` that rejects external domains and potential bypasses (e.g. `//`, `\\`, `///`).
