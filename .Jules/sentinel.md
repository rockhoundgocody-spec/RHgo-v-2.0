## 2026-07-15 - Token Storage Leakage and Open Redirects in Client Parameters
**Vulnerability:** Core application parameters (such as access tokens) were persisted in global localStorage, leaving them exposed long-term to token theft and leakage. Additionally, the parameters system dynamically loaded `from_url` and redirect query parameters from the URL search query without validation, enabling Open Redirect vulnerabilities.
**Learning:** Persisting authentication/session tokens in standard `localStorage` leads to security risks when multiple subdomains or pages run within the same origin, as tokens survive browser/tab sessions. Transitioning sensitive credentials to ephemeral `sessionStorage` reduces exposure windows. Also, any user-supplied or URL-parsed parameter used for navigation redirection must be strictly validated before processing.
**Prevention:** Always route sensitive authentication tokens to `sessionStorage`, actively clear any legacy keys from `localStorage` on load, and strictly sanitize redirect destination paths using a validation helper that rejects protocol-relative, cross-origin, or malicious URL schemes.
